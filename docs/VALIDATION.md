# 验证范围

本页区分原本机版本的已测行为与公开发布构建。原本机测试记录含个人路径和壁纸信息，不随公开仓库分发。此处只记录检查范围和边界，不用模拟数据冒充真实桌面验收。

## 已有自动化检查

预览最大化版本在开发电脑上编译成功，已有 **51 项离线检查通过**。源码中的 `SelfTests.cs` 包含这些检查，主要覆盖：

- 北京时间 22:50 / 23:00、跨日、跨年和错过多日后只补最近一期。
- 缓存复制与校验，包含隐藏文件、中文路径、空目录、文件集合和内容哈希。
- 越界路径、被修改或缺失的缓存、无效媒体与不支持的项目类型拒绝处理。
- 推荐日期隔离、过期下载结果、忙碌或重复操作、错误状态和暂停恢复。
- 最近 10 次选择、当前候选、当前壁纸与预览租用资源的清理保护。
- 悬停预览校验结果复用、资源释放、文件变动失效及同大小文件篡改识别。

这些检查使用临时样本和受控状态，不需要把真实工坊壁纸打包到测试目录。通过结果不等同于 Steam 下载、完整动态播放或重启登录的端到端测试。

- 实际启动隔离测试子进程，验证取消、退出及进度回调异常后进程已经结束；实际创建测试目录链接，验证清理拒绝越界且目标文件完整。预览取消后的延迟窗口关闭使用假时钟和窗口回调测试，没有模拟真实 Wallpaper Engine 窗口。
- 测试在外部进程启动边界记录实际调用；未授权调用为 0。不再使用固定填写的安全汇总，也不宣称进行了操作系统级文件访问审计。
- 冻结源码打包后核对源码文件集合及所有文件哈希未被构建修改。ZIP 的文件集合和逐文件哈希检查通过。源码 ZIP 在 Git 仓库外、含空格目录重新构建并通过全部 100 项测试；无需安装新 SDK。
- 本轮没有重新进行真实工坊下载、实际桌面切换或物理重启。历史实机结果仅证明当时版本，不能代替本版的完整实机验收。

自动构建定义保存在 `docs/windows-build.yml`。GitHub 连接器拒绝上传工作流（403），当前命令行授权也不含 `workflow` 权限；因此本次已完成的是本地自动化检查。获得授权后，将该文件放入 `.github/workflows/windows-build.yml` 即可启用。此权限问题不影响源码、程序和 Release 的发布。
